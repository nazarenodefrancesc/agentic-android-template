# v0.1.2 — Semantic versus rendered visual evidence

## Motivation

A prior Android project showed that a Compose test could pass because an icon node and
content description were present, while the intended glyph was not visibly painted on
the physical device.

## New rule

Semantic/accessibility assertions validate semantic presence, accessibility and interaction:
node existence, content descriptions, text, enabled state, click behavior and input/state
changes. They do not prove that pixels, colors, shapes, icons, spacing, clipping or
contrast render correctly. A visual acceptance criterion must name separate rendered
evidence: an explicitly adopted visual test or physical-device human acceptance.

`assertIsDisplayed()` must never be reported as proof of pixel correctness. Screenshot or
golden testing remains optional and must not be introduced automatically for one visual
criterion.

## Deliberately not added

- screenshot or golden-image framework;
- pixel-diff infrastructure;
- Telegram artifact deduplication or delivery redesign;
- managed-device task repair;
- icon libraries or runtime architecture changes.

## Derivation smoke result

The official `scripts/new-app.sh` path was run against the committed patch HEAD in a
temporary directory. It produced an independent Git repository, rewrote package/name
placeholders, removed template-only `TEMPLATE.md`, retained `TEMPLATE_ORIGIN.md`, and
inherited the semantic/visual guidance and evidence template. The derived task metadata
validated with `task.py validate`. No temporary directory remains.

## Deferred observations

- Managed-device execution remains unavailable because the expected task is environment-
  dependent; repairing it is outside this patch.
- Optional rendered screenshot evidence may be useful after more than one project
  demonstrates recurring demand; no baseline framework is justified by this single case.

## Risk assessment

- Application runtime code: unchanged.
- Gradle/build behavior: unchanged.
- QA signing/provenance: unchanged.
- Task lifecycle: unchanged; only evidence wording/templates were clarified.
- Generated app architecture: unchanged.

The patch is documentation/guidance and scaffolding only. It does not alter Android
runtime behavior or weaken any existing gate.
