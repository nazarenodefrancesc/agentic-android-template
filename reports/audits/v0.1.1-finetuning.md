# v0.1.1 Finetuning Audit

Date: 2026-08-26

## Why this pass was necessary

A second audit focused on defects that would affect the first real server/app trial rather than adding generic architecture.

## Changes made

1. Updated Android Gradle Plugin from 9.3.0 to 9.3.2 after the current Android Studio/AGP release stream exposed a JDK 17 lint crash in the 9.3 line. Gradle remains 9.5.0 and the project remains on API 37 / Compose BOM 2026.08.00.
2. Removed an accidentally tracked Python `__pycache__` and added repository guards preventing generated Python cache files from being committed again.
3. Made Gradle-wrapper bootstrap cache shared across derived apps and prevented first bootstrap from rewriting tracked launcher files.
4. Added `scripts/template-self-test.sh`, an Android-SDK-independent regression test for new-app derivation and task lifecycle behavior.
5. Hardened task metadata validation with filename/ID consistency and dependency-cycle detection.
6. Added lifecycle-transition guards so tasks cannot jump arbitrarily between states.
7. Formalized physical acceptance: human-required tasks cannot become COMPLETE until acceptance of an identified packaged QA APK is recorded.
8. Bound acceptance evidence to QA checksum/metadata, clean Git provenance, passed fast gates and signing-certificate identity.
9. QA builds now reject dirty Git trees by default so a build SHA identifies the exact source used for the APK.
10. QA packaging now verifies the APK with `apksigner` and records the signing certificate SHA-256 fingerprint.
11. Server preflight now also checks `platform-tools`, `adb` and `apksigner` availability.

## Still intentionally pending

This packaging environment cannot resolve Gradle/Maven dependencies or host an Android SDK/emulator, so the following remain the first server falsification gates:

- AGP/Kotlin/Compose dependency resolution and compilation;
- Android lint execution;
- JVM/Android Gradle test execution;
- managed-device test execution;
- real QA APK assembly;
- real `apksigner` verification of that APK;
- repeated install/update on the physical Pixel using the persistent QA key.

No pending gate is treated as implicitly passing.
